# Metro View —— 地铁数据查看、路线规划与设备协同客户端

[![Android](https://img.shields.io/badge/Android-8.0%2B-brightgreen)](https://developer.android.com)
[![License](https://img.shields.io/badge/License-Apache%202.0-blue.svg)](LICENSE)

> 专为 [Metro Editor](https://gitee.com/rabbitc/metro_editor) 设计的 Android 数据消费端。加载 JSON / `.bmetro` 同步数据，浏览线路地图，使用多种策略进行路径规划，并支持站点打卡、多站点任务链、通勤距离计算、历史行程、收藏路线管理以及与桌面端的双向同步。

## 📌 项目定位

**Metro View** 是 `metro_editor` 的配套移动客户端，承担“数据查看与规划”角色，**不包含任何编辑功能**。

- **数据源**：本地或网络 JSON，或由 `metro_editor` 编译后通过 TCP 推送的 GZip 压缩 `.bmetro`。
- **运行平台**：Android
- **核心价值**：将编辑器产出的静态数据转化为可交互地图与路径规划引擎，并提供移动端记录采集与桌面端协同能力。

## ✨ 核心功能

### 🗺️ 交互式地铁地图
- 加载本地或网络 JSON 数据，离线渲染地铁拓扑图。
- 支持缩放、平移、点击查看站点/线路详情。
- 按线路颜色区分显示，换乘站特殊标识。
- 支持按线路名称筛选显示（聚焦单条线路）。

### ⭐ 收藏路线管理
- 主界面收藏区会根据起点站或终点站输入自动筛选，最多显示前 3 条。
- 收藏路线显示为“标签（起点 → 终点）”或“起点 → 终点”。
- 点击“管理”或“查看全部收藏路线”进入收藏路线管理页。
- 收藏路线管理页支持查看全部、编辑、删除、上移/下移排序。

### 🔄 与 MetroEditor 设备同步
- 桌面端启动「设备同步」服务后，App 可通过 TCP（默认端口 28080）连接并接收 `.bmetro` 数据，自动导入并刷新地图。
- 支持 UDP 局域网自动发现（端口 28081）：PC 广播搜索设备，手机自动回应；PC 可一键发起连接。
- 支持地图数据推送、打卡/历史行程导出与回传，记录以 JSON 双向合并去重。

### 🧭 8 种路径规划算法
内置完整的路径计算模块，涵盖日常出行与特殊场景需求：

| 算法类别 | 具体策略 |
| :--- | :--- |
| **效率优先** | 最短时间、最短距离、最少换乘、最少站点 |
| **费用优先** | 氪金路线（票价权重优先） |
| **体验/探索** | 破产路线、随机路径（随机生成可行路线） |
| **综合/高级** | 避开拥挤区段（需数据标记） |
| **自定义权重** | 距离、换乘、票价、时间、站点数、拥挤度滑动条调整 |

> 规划结果以列表 + 分段指引形式清晰展示，支持结果间一键切换对比。

### 📊 线路规划信息查看
- 每条线路的基础属性：运营时间、发车间隔、线路里程（视数据完整度而定）。
- 站点详情页：所属线路、相邻站点、是否换乘站及换乘预估步行时间。
- 路径规划结果附带详细的**逐站指引**（途经站名、方向说明）。

### 📍 站点打卡与附近站点
- 基于定位查找附近站点（默认 5 km），可一键填入起终点：点击填起点、长按填终点。
- 支持手动输入站点打卡，自动记录城市、经纬度与距离。
- 打卡支持多张照片、备注、日期和小作文（HTML 渲染）。
- 打卡详情页竖向展示全部照片，支持单张删除、添加多图、拍照。
- 支持现场打卡判定：1000 米内可现场打卡，拍照或 EXIF GPS 可作为现场凭证；否则为手动补卡。
- 打卡列表显示城市、站名、时间、距离、备注和照片数量，并支持站名搜索。
- 记录可修改、删除（删除需确认），最多保存 500 条，可通过 TCP 导出到 PC。

### 🧩 多站点打卡任务链
- 支持起点、终点和任意数量中间待打卡站点。
- 使用贪心排序 + 2-opt 优化生成打卡顺序。
- 自动计算相邻站点的实际地铁线路、方向、站数和换乘信息。
- 任务链列表可展开/收缩，分段显示线路颜色。
- 每个任务步骤可直接进入新增打卡页。

### 🧾 历史行程
- 路线规划成功后自动保存行程（起终点、时间、里程、换乘、票价、耗时、途经站、模式）。
- 按当前城市过滤，不显示其他城市记录。
- 支持按起点、终点或模式查询。
- 自动删除起点、终点和行程信息完全相同的重复记录。
- 点击历史记录会恢复完整路径，避免随机/最长路线重新计算后结果变化。
- 支持通过 TCP 与桌面端双向同步，按业务键去重合并。

### 🚉 通勤距离计算
- 输入家附近坐标或最近地铁站 + 步行距离，并输入公司详细地址。
- 使用高德地理编码解析公司地址。
- 自动计算家和公司最近地铁站、步行距离以及实际地铁行程。
- 支持并行计算、ListView 分段展示，并保存为“通勤查询”历史记录。

## 🔄 与 Metro Editor 的数据协作

| 环节 | 工具 | 职责 |
| :--- | :--- | :--- |
| **数据生产** | `metro_editor`（桌面端） | 图形化编辑、编译输出标准 JSON / `.bmetro` |
| **设备协同** | `metro_editor`（桌面端） | TCP 推送、UDP 发现、记录导入导出 |
| **数据消费** | `Metro View`（本应用） | 加载数据、渲染地图、执行规划、采集并回传记录 |

工作流简图：
`编辑数据 → 编译导出 JSON → TCP/UDP 同步至移动端 → App 自动导入并解析 → 交互、规划与记录采集`

## 🛠 技术栈

- **开发语言**：Java（Android SDK）
- **UI 框架**：Material Design / AndroidX
- **地图渲染**：自定义 Canvas 绘制（无第三方地图 SDK 依赖，完全离线）
- **网络通信**：TCP 长连接同步（小端序长度前缀帧）+ UDP 局域网发现
- **图像处理**：相册/拍照图片压缩为 Base64，支持 JPEG 缩放与还原
- **定位服务**：WGS-84 → GCJ-02 坐标转换 + Haversine 距离计算
- **数据解析**：Gson + GZip 解压
- **路径算法**：Dijkstra / A* 变形 + DFS 随机策略 + 动态权重评分
- **本地存储**：SharedPreferences（打卡记录、历史行程与用户偏好设置）

## 📂 数据格式要求

本应用支持 `metro_editor` 输出的标准 JSON 文件，以及通过 TCP 同步传输的 GZip 压缩 `.bmetro`（压缩前为同一 JSON 数据）。移动端按需解析线路、站点、换乘与票务等核心字段；区域、运营公司、背景图、路段类型、交路、快车停靠、其他语言站名等扩展字段由 `metro_editor` 输出，供后续展示与扩展。

以下为简化示例，详细字段定义请参考 `metro_editor` 项目文档。

```json
{
  "lines": [
    {
      "id": "line_1",
      "name": "1号线",
      "color": "#FF5722",
      "stations": ["A站", "B站", "C站"],
      "travelTimes": [120, 90]
    }
  ],
  "transfers": [
    {"from": "B站", "to": "D站", "walkMinutes": 3}
  ],
  "fareRules": [...]
}
```

## 📱 快速开始

1. 在 `metro_editor` 中完成数据编辑并编译，得到 `.json` 文件。
2. 手动导入：将文件放入手机存储，或上传至内网服务器获取 URL；打开 App → 选择“导入数据” → 指向本地文件或输入 URL。
3. 设备同步（推荐）：桌面端打开「工具 → 设备同步 → 启动服务」，App 首页点击「🔄 设备同步」并输入 IP/端口；或由桌面端「自动搜索设备」发现手机后一键连接。
4. 同步成功或加载成功后，即可浏览地图、规划路线，并使用首页的附近站点、打卡、历史行程与收藏路线管理功能。

## 🔐 权限说明

- `INTERNET` / `ACCESS_NETWORK_STATE`：用于 TCP 同步与 UDP 设备发现。
- `ACCESS_FINE_LOCATION` / `ACCESS_COARSE_LOCATION`：用于查找附近站点。
- 相机 / 相册：运行时申请，仅用于打卡图片；拒绝授权仍可进行文字打卡。
